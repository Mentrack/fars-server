# 2026-10-17 — CAMF analysis reads camfRate

## Problem

`POST /api/analysis/perform` with type `CAMF` named its local rate `camfRate` but assigned `rate.debitRate || 1`. A saved `camfRate` never affected the charge. On a mock account with `camfRate` 1, `debitRate` 5 and ₦1,200,000 of turnover, the client CAMF was ₦6,000 instead of ₦1,200.

## Approach

The charge now uses `rate.camfRate`. A null `camfRate` still defaults to `1` per ₦1,000. `0` is kept, so a negotiated zero rate is not replaced by the default. `debitRate` is no longer read here.

Accounts that only filled `debitRate`, and left `camfRate` empty, will now be charged at `1` per ₦1,000 instead of `debitRate`.

## Affected modules

- `src/analysis/strategies/camf.strategy.ts`
- `src/analysis/strategies/camf.strategy.spec.ts`

## Migration / deploy

No Prisma migration. Deploy the API. Rates that should not use the default of `1` need `camfRate` set.

## Still wrong

A missing `vatRate` still becomes `0.075` and is then divided by 100. `excess` is still `NaN` when the CAMF date has no VAT line. Only `bankAccounts[0]` is analysed.
